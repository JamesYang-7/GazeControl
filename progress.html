Done Mouth interior fixed properly (real mouth-bag geometry) 2026-08-02 in Virtual agents
the body FBX was replaced with a Blender re-export that carries an actual mouth bag, and that geometry is split onto its own submesh with a dark material at import time. Retires the MouthCavity/MouthBackdrop blockers entirely: they are deleted from the scene, along with MouthCavityTools.cs and MouthCavity.mat
  • The bag carries no UV mapping. All 161 of its vertices (129 new ones plus the inner-lip rim that was merged into them) collapse onto UV (0, 0), so the whole cavity samples a single texel — the bottom-left corner of whichever albedo the agent wears. That corner is RGB(77, 85, 84) in the stock 4096² SMPL-X atlas (reads black) but RGB(245, 246, 241) in the 512² SMPLitex one, which is exactly why Agent A looked right and Agent B looked grey. Nothing else uses that texel: the nearest mapped UV is 0.029 away (15 px at 512², 120 px at 4096²).
  • SmplxMouthInteriorSubmesh (an AssetPostprocessor) moves every triangle whose three vertices all sit on UV (0, 0) — exactly 288 of the mesh's 21196 — onto submesh 1 and assigns SMPLX-MouthInterior.mat (URP Lit, base colour 0.055/0.02/0.02). There are no partially-mapped seam triangles, so the rule has no edge cases. Idempotent across reimports, and the scene needed no overrides: the second material slot is inherited from the model prefab.
  • The FBX swap was a true drop-in. Same node names (plus 15 unbound *_end leaf bones from Blender), same single source material, and the 520 blendshapes identical in name and order — so visemes stay at 506-519. Overwriting the asset in place kept its GUID, and both agents kept their materials, bone bindings and lipsync morph targets. Source vertices went 10475 → 10604; the file roughly doubled to 58 MB in LFS.

Blocker-era tuning notes are dropped with the approach; the one durable gotcha — that renders in the *same* editor command as a state change show stale geometry — is already in CLAUDE.md.
